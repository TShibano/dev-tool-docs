# Documentation Checklist

Use this checklist when creating or reviewing documentation for Python development tools.

## Content Structure

- [ ] **Overview**: Clear explanation of what the tool does
- [ ] **Installation**: Multiple installation methods covered
- [ ] **Quick Start**: Simple example to get users started immediately
- [ ] **Basic Usage**: Core commands and functionality
- [ ] **Configuration**: Configuration files and common options
- [ ] **Advanced Usage**: Power user features and complex scenarios
- [ ] **Examples**: Real-world use cases with code samples
- [ ] **Troubleshooting**: Common problems and solutions
- [ ] **Best Practices**: Recommended approaches and patterns
- [ ] **Resources**: Links to official docs, repos, communities

## Quality Checks

### Accuracy
- [ ] All code examples have been tested
- [ ] Version numbers are current
- [ ] Commands work as documented
- [ ] Links are valid and accessible

### Clarity
- [ ] Technical terms are explained
- [ ] Examples include expected output
- [ ] Step-by-step instructions are clear
- [ ] Code blocks are properly formatted

### Completeness
- [ ] Installation covers major platforms
- [ ] Common use cases are addressed
- [ ] Integration with other tools is covered
- [ ] Error messages are explained

### Usability
- [ ] Table of contents is provided for long documents
- [ ] Cross-references between sections
- [ ] Consistent formatting throughout
- [ ] Code examples are copy-pasteable

## Japanese Localization (if applicable)

- [ ] Technical terms have Japanese explanations
- [ ] Examples use appropriate context
- [ ] Cultural considerations are addressed
- [ ] Directory paths use forward slashes

## Maintenance

- [ ] Review date is noted
- [ ] Update schedule is planned
- [ ] Version compatibility is documented
- [ ] Deprecated features are marked
